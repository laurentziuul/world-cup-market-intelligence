\# v0.7.0 Roadmap — Historical Trends and Signal Intelligence



`v0.7.0` is the next major development milestone for World Cup Market Intelligence.



The goal is to move the project beyond static dashboards and toward a real market intelligence system.



The main theme is:



```text

historical trends + signal intelligence

```



\---



\## Current foundation



As of `v0.6.x`, the project already supports:



```text

stable manual CSV workflow

experimental Polymarket live provider

separate stable dashboard

separate Polymarket dashboard

provider registry

provider validation

YES-only Polymarket winner ranking

clear stable vs experimental documentation

generated-output safety rules

```



This gives the project a clean base for historical intelligence.



\---



\## v0.7.0 goal



The goal of `v0.7.0` is to track how market probabilities change over time and surface useful signals.



The project should be able to answer questions such as:



```text

Which teams are gaining probability?

Which teams are losing probability?

Which markets moved the most since the last snapshot?

Which moves are meaningful versus noise?

Which teams have increasing liquidity?

Which events or matches may explain the movement?

```



\---



\## Core concepts



`v0.7.0` should introduce or improve these concepts:



```text

historical snapshots

probability deltas

top movers

liquidity movement

signal classification

event/catalyst notes

dashboard trend sections

```



\---



\## Historical snapshots



The project already stores processed snapshots.



Relevant path:



```text

data/processed/snapshots/

```



`v0.7.0` should make historical snapshot analysis more explicit.



The system should be able to compare:



```text

latest snapshot

previous snapshot

older snapshots

provider-specific snapshots

```



\---



\## Probability deltas



The system should calculate changes such as:



```text

1-day change

7-day change

change since first snapshot

change since last snapshot

```



Example output:



```text

France: 15.20% → 16.10% = +0.90 percentage points

Spain: 14.80% → 13.90% = -0.90 percentage points

```



The focus should be on percentage-point changes, not only raw probabilities.



\---



\## Top movers



The system should identify:



```text

largest positive movers

largest negative movers

largest liquidity increases

largest liquidity decreases

```



This can become a new dashboard section.



Example:



```text

Top positive movers

1\. Germany +1.40 pp

2\. Argentina +1.10 pp

3\. Brazil +0.80 pp

```



\---



\## Signal classification



Raw movement is not enough.



The system should classify movement into simple signal categories:



```text

strong positive move

moderate positive move

flat / no signal

moderate negative move

strong negative move

liquidity spike

low-liquidity noise

```



Initial rules can be simple and transparent.



Example:



```text

+2.00 pp or more = strong positive move

+0.75 pp to +1.99 pp = moderate positive move

\-0.75 pp to -1.99 pp = moderate negative move

\-2.00 pp or less = strong negative move

```



These rules can evolve later.



\---



\## Catalyst notes



`v0.7.0` should prepare the system for event and narrative context.



Possible catalysts:



```text

match result

injury news

squad announcement

managerial change

betting-market liquidity spike

media narrative shift

tournament bracket implications

```



At first, this can be manual.



Later, it can become semi-automated.



\---



\## Dashboard improvements



The dashboards should eventually include:



```text

current ranking

probability change since previous snapshot

top movers

liquidity movers

signal label

last updated timestamp

provider status

```



The stable dashboard and experimental Polymarket dashboard should remain separate.

Suggested implementation path:

v0.7.4 — Add top movers output

\---



\## Non-goals for v0.7.0



`v0.7.0` should not attempt to solve everything.



Not included yet:



```text

fully automated news ingestion

automated social media narrative extraction

multi-provider arbitrage

betting recommendations

trading signals

financial advice

scheduled cloud deployment

```



The focus remains market intelligence, not betting advice.



\---



\## Success criteria



`v0.7.0` is successful if the project can clearly show:



```text

current probabilities

historical probability changes

top positive movers

top negative movers

basic signal classification

clear dashboard presentation

reproducible trend outputs

stable vs experimental separation preserved

```



\---



\## Final principle



The project should remain:



```text

transparent

provider-agnostic

educational

research-oriented

not betting advice

```



`v0.7.0` should make the system smarter without making it opaque.
