## Data freshness utility

Added:

- scripts/check_data_freshness.py

This utility checks whether key dashboards and generated outputs are:

- available
- missing
- fresh
- stale

It reports:

- last modified time
- file age
- stale status
- missing files
- summary counts

Run:

- python scripts/check_data_freshness.py

Optional commands:

- python scripts/check_data_freshness.py --stale-hours 24
- python scripts/check_data_freshness.py --show-stale-only
- python scripts/check_data_freshness.py --show-missing-only

Default stale threshold:

- 72 hours

Freshness does not mean correctness.

Freshness only means a file was generated recently.

## Why this matters

A public intelligence dashboard should not only show data.

It should also explain whether the data is fresh, stale, missing or experimental.

The trust layer helps users understand:

- whether a dashboard was generated recently
- whether output files are missing
- whether generated outputs are stale
- whether live-provider layers are experimental
- whether manual review is needed

This reduces overclaiming and improves public credibility.

---

## Stable vs experimental interpretation

Stable layer:

- manual_csv provider
- manual market CSV
- stable dashboard
- reproducible offline workflow

Experimental layers:

- Polymarket live provider
- historical trends
- catalyst notes
- narrative intelligence
- team intelligence
- dashboard trust metadata

The trust layer improves transparency.

It does not make experimental data predictive.
